## Root causes on the pinned base (verified at base SHA, kernel blob fa30e120)

1. **Turn identity is not input-complete and not deployment-scoped.** `turnDispositionIdentity` (kernel ~L2926-2933) binds only `kernelModuleSha256`, `{workflowId, instanceKey}`, `turn`, `intentType`. The canonical input payload is absent, so a re-send of the SAME messageId with a DIFFERENT input replays the first turn's stored receipt as `idempotentReplay` (a lie: the changed-input conflict never fires); and no `[deployedAppId,tenantId,appId,businessPackageId]` tuple participates, so identity is not injective across deployments. Module SHA inside the identity also conflates pinned-build identity with stable target identity (unstable across releases).
2. **The original acknowledged receipt is not persisted with the state CAS.** `submitOccurrence` commits the authoritative state CAS (~L5233 `commitAcceptedTransitionInLane`), then builds the original receipt (~L5308) and stores it as a SEPARATE best-effort turn-disposition record (~L5294 `writeTurnDisposition`). The replay path `admittedControlTurnHistoryReplay` (~L4721-4746) reconstructs a pseudo-receipt from the NEWEST committed snapshot when the disposition record is missing — after later transitions it cannot truthfully recover the original acknowledged receipt (state/digest drift = lie), and the crash window between CAS and best-effort write is exactly where the receipt is lost.
3. **Disposition loss permanently blocks progress at 16+ turns.** `MAX_ADMITTED_CONTROL_TURN_HISTORY = 16` (~L2924) and the eviction gate (~L5047-5063) refuse ALL new turns while the oldest bounded-history entry's independent disposition record is missing. A lost derived disposition wedges the instance forever (17+ turns impossible; livelock).
4. **Physical doc keys are not deployment/B-scoped.** `instanceDocKey` (~L2518), `admissionFenceDocKey` (~L2541) and the journal/effect/disposition/receipt key families derive only from `workflowId`/`instanceKey`(/turnId). Two deployed B sharing `workflowId`+`instanceKey` collide on ONE physical store (instance, fence, journal, effects, receipts all cross-read).

## Exact behavior contract (L3 checkpoint: Tests → Contract → Implementation → Failure Handling → Reference)

### Tests (written first; see TEST_MATRIX.yaml)
P: same-CAS original receipt + state in ONE physical put (revision == stateRevision, restart-durable); identical retry replays the exact original receipt `idempotentReplay` with zero new journal/effect activity; 17+ distinct turns after ALL derived archive records are destroyed keep admitting and turn-1 replay still answers from the same-CAS receipt; restart mid-sequence; two B namespaces over one SQLite file; two real Node24 processes racing one turn.
N: same messageId + canonically-changed input refuses typed `K02_TURN_RECEIPT_INPUT_CONFLICT` BEFORE any admission/effect; same messageId + different intentType refuses typed; foreign-B read/replay of another deployment's keys is impossible (no cross-namespace key reachability); competing writer cannot forge an ACK (CAS loser never fabricates a receipt).
F: fatal store fault on the receipt CAS fails closed typed (no partial claim of atomicity); unreadable/legacy envelope shape (pre-1.0, missing `inputDigest`) fails closed typed `K02_TURN_RECEIPT_LEGACY_UNREADABLE` (no migration); ring eviction never blocks on a missing archive record.

### Contract (post-fix invariants; none weakened vs base)
1. **Same-CAS original receipt.** The immutable original acknowledged logical receipt of every admitted turn is a field of the SAME single document value written by the authoritative instance state CAS (`mustMatchRevision` at the observed revision). There is no window where the state is committed and the original receipt is not (one physical row write makes both durable together or not at all). Optional observational metadata (archive copies, observers) remains optional and never falsifies the original.
2. **Immutable original.** `durableOriginalReceipts[turnId]` is append-only: later transitions (any count, any writer) never rewrite or evict-with-rewrite an existing entry; a re-admission attempt of an already-admitted turnId is refused before any state mutation.
3. **Injective, stable turn identity.** Turn receipt identity = canonical JSON of `{deploymentScope: [deployedAppId,tenantId,appId,businessPackageId], workflowId, instanceKey, turn, intentType, inputDigest}` where `inputDigest = sha256(canonicalJson(input))`. Identical retry ⇒ identical identity ⇒ replay; changed input or intent ⇒ typed conflict. Pinned-build identity (`moduleSha256`) rides the envelope as a SEPARATE `buildIdentity` field (stable target identity across releases; build switch is observable, not identity-breaking).
4. **Canonical-input equivalence.** Two inputs that are the same JSON value up to key order/whitespace are canonically identical (same digest ⇒ replay); any semantic difference (value, nesting, type) changes the digest ⇒ conflict. Non-JSON-representable input refuses typed at admission.
5. **Disposition liveness (17+).** Progress of NEW turns never depends on the existence of any derived/best-effort record. The same-CAS receipt map is the once-only truth; the bounded in-document ring (default 64 ≥ 4× the frozen 16) evicts the oldest entry only once its independent durable archive record exists (the eviction moment retries that write; on archive fault the entry stays and the document temporarily grows past the bound — admission proceeds, nothing is forgotten). Ring+archive together answer replay; a ring-evicted turn's replay reads its durable archive. A store fault on a replay-path read fails closed typed for THAT turn (a faulting store is not a policy wedge).
6. **Deployment-scoped physical namespace.** Every durable doc key the K stack addresses (instance, admission fence, effect journal, turn disposition, decision receipt, original-receipt archive) is namespaced by the injective scope tuple `[deployedAppId,tenantId,appId,businessPackageId]`. Two B with identical `workflowId`+`instanceKey` occupy disjoint physical keys on ONE store; neither can read, fence, journal or receipt the other's instance. Key grammar is pure composition over the Host docs port (works over the unmodified selected kernel today; splice into kernel key builders post-K01 for default behavior).
7. **Fail-closed store truth.** A faulting CAS put fails typed with zero durable partial state; a closed/unreadable store never yields a synthesized receipt; `HOST_KEY_EXISTS`/`HOST_CAS_CONFLICT` lose honestly.
8. **K01 fence/effect protections untouched.** K02 phase-1 adds zero edits inside `kernel-mechanism-v1.mjs`; the two-B namespace test runs the REAL unmodified kernel through the scoped adapter, so the admission-fence CAS discipline and effect-journal semantics of the base (incl. K01's in-flight work target) are exercised, not weakened.
