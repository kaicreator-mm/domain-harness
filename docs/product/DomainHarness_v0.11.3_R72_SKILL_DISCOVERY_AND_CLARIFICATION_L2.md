## L2-C · 候选 API（设计签名，待独审及编译）
- ClarificationElement<E extends string> 私有构造，真实私有 #data 持有 typed E 的深冻结 promptSpec+fieldId→E binding；构造要求 module-local 未导出 token（TS private 单独不够，JS 未授权 new 拒绝），冻结实例，内部读取真实私有字段 brand 并校验工厂 token 创建语义；普通假对象/错误实例/代理冒充不得进入发布。static prepare<K extends string,E extends string,V>(evidence:EvidenceResolution<E,V>,selection:DecisionSelection<K>,template:Omit<InteractionPromptSpec,'fields'>,fields:readonly ClarificationField<E,V>[]): ClarificationPreparation<E>。保留 ready/failed/unresolved/blocked/conflict 的原状态/原因；prompt 分支变为 {status:'prompt', clarification: ClarificationElement<E>}。普通 API 不公开内部 binding，不要求访问可见 spec；显示只取 A 发布的 InteractionPrompt。
- InteractionDecision<S,I,E extends string=string> 保留 ready；clarify 分支明确互斥：{kind:'clarify',state:S,prompt:InteractionPromptSpec,clarification?:never,invalidate?} 或 {kind:'clarify',state:S,clarification:ClarificationElement<E>,prompt?:never,invalidate?}。plain prompt 原路径不变。InteractionEvent<E extends string=string> 由 A 从内部 raw event 扩展为 readonly union：initial 保持 records 且 clarification?:never；plain response 保持 response/records 且 clarification?:never；bound response 保持 response/records 且 required readonly clarification: Exclude<ClarificationResponse<E>,{status:'failed'}>。调用者用 event.kind==='response' && event.clarification!==undefined 区分；bound-only 消费者遇到意外 plain response 必须失败收敛，禁止从 raw values 重建配对。失败由 A 返回 FAILED/INTERACTION_CLARIFICATION_BINDING_FAILED，决策回调不进入；其他原状态不变。A 的 scope.resolve<S,I,E=string>、F runInteractiveRecognitionHandling<S,I,O,E=string> 贯通键类型，不强制所有 raw 消费者更改泛型。实际 TS 负例用明确 Key 泛型（包括 checkpoint/F）拒绝错误 key 类型、双路径；string/union 推断有意较宽，不替业务证明 key。JS 实际两条路径同时存在或均无有效路径、假 bound 对象/未授权构造/无真实品牌实例，均按 L2-D 在等待预留之前失败不发布。此为交互输入合同，不是验证整个 Package。
- A constructor onPrompt?: (prompt:InteractionPrompt,interaction:InteractionElement)=>void，直接通知实际实例；原单参 callback 仍可用。保留原 return 检查/观察 Promise rejection；不让业务为了得到实例或捕获 prompt 再包装通知。
- 旧 buildClarification/mapClarificationResponse 实现保留为内部纯函数及原测试（改名 RawClarificationPreparation 内部形状），不再根公开；实际生产消费者只有四个已迁移路径，standalone 预览/映射暂无独立实际用途（若独审举出必要独立用例，审定保留 build-only 低级纯入口，不保留可误用配对为普通路径）。不删除旧行为，冻结 L1/L2 允许等价组织；当前阶段未发布，不新设兼容层。预期根28-2+1=27 个运行值；现有61独立类型名称可保持（ClarificationPreparation prompt 形状/InteractionEvent/Decision/Scope 类型更新），独审冻结准确集合，不能按数字机械执行。具体 Standard Element 增至11（非数量目标）。若最终类型/符号变化另列准确 delta。

## L2-D · 关联不变量及预算
1. 域调用 prepare：现有 build 规则不变（候选完整性、预填不是确认、适用性/冲突/无合法项、域提供真实证据和策略），生成不可变请求。域自己选择正确准备结果；SDK 不推断域选错的业务 key。
2. A 在 #resolve 处理 clarify 时，先识别 raw/bound 互斥形状（明确恰一真实有效输入；不接受两个字段或无有效输入），bound 通过 E 固定内部 accessor 读取真实 factory-issued 私有字段及不可变 spec/binding，捕获为该次循环局部值；非法形状/假实例/无法读取/非法 prompt → FAILED/INTERACTION_INVALID_PROMPT，在本轮 decide 已计费之后、等待预留和任何发布/通知之前失败。调用原 makePrompt 生成唯一实际 prompt；先预留原等待1call/1step，后实际通知/等待。无可变 binding 泄漏给 client；原 submit 接口/协议不变。无新 root、计数器、通知队列或取消机制。
3. A #wait 原合法捕获及回调失败处理；取消/拒绝/async通知失败、不足预算均禁止后续映射及业务处理。合法响应按原记录/修订失效逻辑生成 raw event。**只在下一次 decide 的既有 root.invokeOutcome 已预留额度后**，以同一个真实 prompt + 已捕获 bound 实例 + raw event/latest valid record 映射显式用户值；生成冻结 typed event，不接受调用方另传 prepared/prompt/event 以重绑定。映射失败在进入业务 decide 前稳定 FAILED，不晋升证据；临时绑定在交付/失败/取消/根结束后释放，不跨 resolve checkpoint/根/实例继承。仍允许域在有效新分析中主动重新准备；动作映射严格按下表，plain route 不映射，A reject/cancel 不进入后续 decide。接受 wire ACK 仅表示 A 捕获，不证明映射交付、权限或 Handling；通知失败/取消仍可使已捕获 ACK 后的实际执行失败。
4. 不额外计费 pure mapping，保留原最短全输入2call/3step、一次澄清4/5、两次6/7，不改变实际专业 IO、授权和 Effect 计费。域负责 reducer、当前事实/候选合法性、失效重算、独立权限、专业操作；前一轮 mapping 不能充当当前授权。
5. 迁移 media/workshop/Reference/procurement 四域：删除 prepared+lastPrompt 手工配对/仅为配对的通知包装，使用 event.clarification，原 parse/事实校验/域 reducer/solver/receipt/授权不变。R65 原 initial/maintained SHA 和日志不改写，另加明确 integrator follow-up。UI/CLI actual client wire schema 不变；不新增 LLM runtime。
### L2-D.1 · 绑定事件动作表（P1-R73-01 冻结）
以下仅 bound 路径，在下一次 root.invokeOutcome 已成功预留 1call/1step、调用域 decide 之前，原记录失效/新增逻辑完成后映射；仅实际最新 valid record 的 response identity，客户端原 wire 和 raw payload 保持。initial 无 clarification；plain response 无 clarification，不重构映射。
| 实际动作/条件 | 交付或失败 | 记录与领域边界 |
|---|---|---|
| submit | clarification.status=values, action=submit, values=实际显式字段映射，origin=user | 同 decisionKey 旧记录失效，新实际 record valid；不填默认/隐式授权 |
| revise + values | clarification.status=values, action=revise, values=实际显式字段映射，origin=user | 原有效记录全部失效，新实际 record valid；域按 B 依赖重算，不能丢 revise values |
| revise + text | clarification.status=other, action=revise；event.response 保留 text | 原有效记录全部失效，新 record valid；域解释文本或拒绝，不假造 values |
| text | clarification.status=other, action=text，raw text 保留 | 同 decisionKey 旧记录失效，新 record valid；域处理 |
| no-fit | clarification.status=other, action=no-fit，raw 保留 | 同 decisionKey 旧记录失效，新 record valid；域重算或拒绝，非 READY |
| reject / cancel | 原 REJECT/INTERACTION_REJECTED 或 CANCELLED | 不映射、不进入下一 decide/Handling |
| 通知 throw/非 undefined return（含 Promise resolve/reject、已同步捕获 ACK） | 原 FAILED/INTERACTION_NOTIFICATION_FAILED（实际观察 Promise rejection） | 不映射、不交付、不 Handling；取消沿原合同 |
| 下一分析额度不足、已取消 | 原预算失败或 REJECT/CANCELLED | 不调用 mapper/decide/Handling；原接受记录不表示业务已执行 |
| 无效 bound/raw 决策或无真实 factory-issued instance | FAILED/INTERACTION_INVALID_PROMPT | 本次 decide 已计费，无等待预留/发布/通知 |
| 已捕获真实 bound 的 mapping 校验失败 | FAILED/INTERACTION_CLARIFICATION_BINDING_FAILED | 仅在已预留下一分析的回调内，禁止产生 usable mapped event、禁止域 decide/Handling |

每次实际发布只使用已捕获的 immutable binding；同一准备在新真实发布/另一实例的独立 occurrence 可以复用，但不允许复用前次事件或跨 checkpoint 继承；无 global registry。需用真实 revise-values/text/no-fit、same visible/different binding、wrong-key TS、假 JS 对象/构造、原 notify 第二参实际身份、raw/bound mixed、两个 checkpoint/并行实例、预算 exact/short 和当前 record identity 的正负对照及去掉真实捕获/错误映射变异验证。
