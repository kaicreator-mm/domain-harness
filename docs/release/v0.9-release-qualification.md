# DomainHarness v0.9 — Release Qualification (N09 #1037)

State record; see `docs/validation/v0.9/n09-release-qualification.md` for the
full evidence matrix (candidate SHA, run records, hidden validation, security
review verdict). Quickstart: `docs/quickstart/v09/index.md`; worked example:
`examples/v09-clean-consumer/`.

## What v0.9 ships

- `@kaicreator/domain-harness/v9` — the public consumer app API: the frozen
  `DomainHarness` value whose single verb is `load(installedRef)`, plus the
  frozen public error families (`PACKAGE_NOT_AUTHORIZED`, `CALLER_SCOPE_DENIED`,
  `OPERATION_NOT_BOUND`, `LIFECYCLE_FAILED`, `EFFECT_UNKNOWN`,
  `UNSUPPORTED_RUNTIME_ABI`).
- `@kaicreator/domain-harness/v9/deployment` — the one deployment-owned
  trusted bootstrap entry (bridge composition + protected-host governance +
  store/issuer/authenticator port types). Deployment materials — physical
  store, issuer secrets, caller authenticator — are the authority; importing
  the entry grants no cross-deployment capability.
- The protected H→K runtime bridge with selected-Kernel admission, one-shot
  physical effect permits on shared per-subject CAS authority, #1120 scoped
  subscribe/stop lifecycle with per-delivery currentness recheck, and the
  AsyncLocalStorage one-selected-trusted-Host-per-request discipline.

## Supported profile (first cohort)

Node 24 ESM (qualified on v24.21.0 / Ubuntu 26.04 build host and clean
external consumers). Git-pin + packed-tarball distribution with committed
byte-fresh dist; no npm registry release, no OS matrix beyond the cohort.

## Consumer upgrade notes

v0.2–v0.8 subpaths are unchanged and additive-only; v0.9 adds exactly two
subpaths (`./v9`, `./v9/deployment`). Consumers pin the exact commit SHA or
tarball SHA256 they validated. There is no v0.1–v0.8 migration obligation.
