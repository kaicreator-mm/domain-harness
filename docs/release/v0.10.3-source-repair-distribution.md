# DomainHarness v0.10.3 — source-repair SDK distribution contract

## Purpose

This is a source and packaging metadata repair for DomainHarness v0.10.3. It does not introduce a new product or SDK version. The original `v0.10.3` Git tag and its GitHub Release remain immutable historical artifacts.

## Version source of truth

The four public SDK packages declare `0.10.3` in their source manifests:

- `@kaicreator/domain-harness-contracts`
- `@kaicreator/domain-harness-microkernel`
- `@kaicreator/domain-harness-build` (producer-side tooling)
- `@kaicreator/domain-harness-host-node` (optional Node Host)

All internal SDK dependency edges are exact `0.10.3`. The root monorepo and consuming `@kaicreator/domain-harness` workspace remain product version `0.2.0`; the consumer uses contracts `0.10.3`. The verifier fails closed if either product version or its lockfile record drifts.

Private Domain Package manifests under `domain-packages/**` are not the four public SDK tarballs or root npm workspaces. Their version policy is independent and is not changed by this correction.

## Repair tag

After independent exact-SHA review, Windows Node 24 physical packaging, CI, DomainHarness-owned clean local consumer install/import smoke and final Release Qualification, the corrected source commit may receive the distinct immutable tag:

`v0.10.3+source-repair.1`

The tag suffix distinguishes the corrected Git source snapshot. Package manifests and tarballs still report the package version `0.10.3`. The original `v0.10.3` tag is never moved or rewritten.

## Source-first build

Run the packer from a clean checkout of the exact repair tag with Node.js >=24:

```bash
node scripts/distribution/pack-sdk-from-tag.mjs --tag 'v0.10.3+source-repair.1' --out /absolute/empty/path/outside/checkout
```

The packer verifies that the checkout HEAD is the exact tag commit, builds in a detached worktree, and packs four selected workspaces without rewriting package manifests. For each tarball, `package/package.json` must be byte-identical to the corresponding source-tag manifest.

`SDK_PROVENANCE.json` records the exact source tag/commit/tree, source manifest Git blob and SHA256, tarball hashes/sizes, Node version, and a `commandResults` array containing each executed command's actual exit code and arguments; absolute host paths in arguments are replaced with `<ABSOLUTE_PATH>` to avoid publishing local usernames or checkout locations. `metadataOverlay` must be `false`.

No npm Registry publication, Tag mutation, or automatic GitHub asset upload is performed by the packer.

## Fail-closed checks

`npm run check:sdk-version-consistency` verifies the four public SDK manifests, their internal dependency graph, the DomainHarness consumer contracts edge and `package-lock.json`. The root build invokes this verifier; root tests include positive and negative cases. The packer passes the package version parsed from the exact source tag as an explicit expected version.

## Release boundary

This repair does not itself authorize a repair tag, GitHub Release, npm publication, `main` merge, or installed Skill/docs-current switch. Those require separate exact-SHA review, Windows Node24 physical packaging, DomainHarness-owned clean local consumer install/import smoke, and final Release Qualification. Downstream project validation is not required.
