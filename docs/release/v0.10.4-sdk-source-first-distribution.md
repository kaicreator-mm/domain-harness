# DomainHarness v0.10.4 — source-first SDK distribution contract

## Purpose

v0.10.4 corrects the source-versus-artifact version discrepancy observed in the v0.10.3 GitHub-only SDK distribution. The published v0.10.3 tag and Release remain immutable historical artifacts; their disclosed metadata-only overlay is not rewritten retroactively.

## Version source of truth

The four public SDK packages are versioned in their source-tag manifests:

- `@kaicreator/domain-harness-contracts`
- `@kaicreator/domain-harness-microkernel`
- `@kaicreator/domain-harness-build` (producer-side only)
- `@kaicreator/domain-harness-host-node` (optional Node Host)

For v0.10.4, each source manifest declares `0.10.4`; all internal SDK dependency edges are exact `0.10.4`. The consuming `@kaicreator/domain-harness` workspace remains its own product version (`0.2.0`) and consumes contracts `0.10.4`.

Private Kernel/Standard Domain Package source manifests under `domain-packages/**` are not public SDK tarballs or root npm workspaces. Their package version policy is independent and is not changed by this SDK alignment repair.

## Build and provenance invariant

Run `scripts/distribution/pack-sdk-from-tag.mjs` from a clean checkout of the exact version tag with Node.js >=24:

```bash
node scripts/distribution/pack-sdk-from-tag.mjs --tag v0.10.4 --out /absolute/empty/path/outside/checkout
```

The builder verifies the tag and source manifests, builds in a detached worktree at the exact tag, and packs the four selected workspaces without editing any package manifest. For each tarball, `package/package.json` must be byte-identical to the corresponding source-tag manifest. The generated `SDK_PROVENANCE.json` records tag/commit/tree, packer commit, source manifest Git blob and SHA256, package manifest parity, tarball hashes/sizes, Node version, and actual validation outcomes.

No metadata overlay, npm Registry publication, Tag mutation, or automatic GitHub asset upload is performed by the packer.

## Fail-closed checks

`npm run check:sdk-version-consistency` checks the four public SDK manifests, their internal dependency graph, the `@kaicreator/domain-harness` contracts edge, and `package-lock.json`. The root build invokes this verifier; root tests include positive and negative verifier cases. The packer passes the exact tag version as an explicit expected version.

## Release boundary

This document and source repair do not authorize a v0.10.4 Tag, GitHub Release, npm publication, `main` merge, or `docs/current` / installed Skill switch. Those require separate exact-SHA review, Windows Node24 physical packaging and downstream consumer validation, and final Release Qualification.
