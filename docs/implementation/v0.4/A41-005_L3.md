## 2. Objective (concern boundary)

Implement the bounded **consumer/verifier, never issuer** closure that
integrates the successor authority/compatibility/composition evidence
into Harness-owned Runtime binding and activation verification without
collapsing authorities:

1. `verifyDacV0041RuntimeBinding` — deterministic §12 verification of one
   complete externally recovered Runtime binding claim: C108 anti-alias
   (request != binding != host-binding, consumed from the A41-001
   foundation separation verifier), §12 seam identity separation
   (including `CompatibilityValidationRef != RuntimeBindingRef` and the
   cross-seam request rulings), exact request association, the A41-003
   C144 two-view association + C107 `COMPATIBLE_VERDICT` precedence gates
   (with the presented result view required to be part of the backing
   evidence set), the A41-004 composition-intake gate, exact subject/
   scope/profile matching against BOTH the intake Manifest evidence and
   the compatibility subject, §10/§11 implementation/Host-Binding
   exactness (no retroactive strengthening of abstract compatibility;
   implementation-specific claims bind the same exact concrete refs),
   C128 two-party issuance evidence, the A41-002 designation-chain walk
   at the binding issuance point with exact leaf issuer/role/scope/profile
   binding, F-07 SoD (C148 self-approval, C149 co-hosting
   permission+disclosure, C169 legitimate multi-role preservation), and
   §14 binding-time currentness (compatibility result view +
   implementation/Host-Binding §8.2 reuse).
2. `verifyDacV0041RuntimeActivation` — deterministic §13 verification of
   the separate technical-admission decision: C142/§16 seam conflation
   bar (the activation issuing role token must differ from the binding
   issuing role token even when one identity holds both designations),
   C155/§13 anti-alias across the activation AND binding identities,
   exact request/binding/composition association, a FULL re-verification
   of the bound binding bundle at the activation point (activation
   manufactures no missing upstream promotion/selection/Manifest/
   compatibility authority), its own C128 evidence and designation chain,
   F-07 SoD, and the §8.2 currentness of the bound `RuntimeBindingRef`
   itself at the activation point.
3. `classifyDacV0041BusinessSorTruthSource` — the §17 external Business
   SoR boundary classifier: Runtime accepted/send-dispatched/provider-
   acknowledged/execution-success/activation state classes are Runtime
   mechanics evidence only (`canManufactureBusinessSorTruth: false`),
   external SoR observation/reconciliation material stays externally
   owned evidence under EXTERNAL_AUTHORITY semantics, and unknown
   provenance classes fail closed.
4. Frozen precedence ladders documented on all three result types
   (structural → carrier → role → alias → association → precedence →
   intake → subject exactness → evidence → authority → SoD →
   currentness), mirroring the structural-dominates-staleness rule of
   C152/C171.

Explicit non-goals (authority ceiling): no RuntimeBindingRef /
RuntimeActivationRef / Runtime-HostBinding issuance, no promotion /
