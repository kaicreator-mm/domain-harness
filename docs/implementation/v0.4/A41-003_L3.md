Implement the bounded **consumer/verifier, never issuer** for the DAC
v0.0.4.1 successor compatibility/capability/refusal/currentness seam:

1. `verifyDacV0041CompatibilityViewAssociation` — C89/F-05/C144 role
   separation and exact association over externally recovered facts:
   `CompatibilityValidationRequestRef != CompatibilityValidationRef !=
   CompatibilityResultRef` (pairwise identity anti-alias, mutable-alias
   rejection, foundation-minted request carriers only), exact association
   request -> validation -> result (any mismatch/swap/reuse fails closed),
   §8 input closure (binding-target association; RuntimeBindingRef can
   never be a compatibility-validation input), identical exact subject
   across both views, ONE validation authority (the two views are views of
   the same authority, never peer authorities), no contradictory
   dispositions inside one co-stored record, no second independently
   issued validation for the same exact subject, validator designation
   (C113) — with the frozen 13-pass order documented on the verifier;
2. `classifyDacV0041CompatibilityPrecedence` — the frozen deterministic
   capability/currentness/unsupported/invalid/stale precedence for
   C84/C85/C98/C99/F-08, COMPOSING (never restating) the A41-001
   foundation Steps 0–3 (descriptor establishment -> capability kind
   blocked/missing-capability with target not judged -> structural
   invalidity FAIL_CLOSED dominating staleness -> STALE -> INCOMPATIBLE
   unsupported binding target), then the compatibility-specific rungs:
   C99 binding-check misclassification (REJECT-class, remains
   binding-authority evidence), C98 contradiction (never select only the
   favorable result), C157 result currentness (invalidated dominates,
   stale/superseded => STALE), C113 validator designation, the
   negative-evidence ceiling (asserted COMPATIBLE requires exactly one
   consistent, current, designated favorable produced result; refusal/
   negative evidence alone can never manufacture a compatibility PASS;
   an empty evidence set never guesses), then the bounded verdict;
3. `verifyDacV0041AuthorityRefusalEvidence` — §4.2 substantive
   refusal-evidence verification for the frozen refusal seams
   (compatibility is NOT one — it carries its own INCOMPATIBLE polarity,
   C142): produced negative decision, designated refusing issuer, bound
   request; the classification structurally carries
   `canManufactureAuthority: false` / `canProduceCompatibilityPass: false`.
