v0.0.4.1 successor compatibility/capability/refusal/currentness seam:

1. `verifyDacV0041CompatibilityViewAssociation` — C89/F-05/C144 role

   `CompatibilityValidationRequestRef != CompatibilityValidationRef !=
   CompatibilityResultRef` (pairwise identity anti-alias, mutable-alias
   rejection, foundation-minted request carriers only), exact association
   request -> validation -> result (any mismatch/swap/reuse fails closed),
   §8 input closure (binding-target association; RuntimeBindingRef can
   never be a compatibility-validation input; a RuntimeHostBindingRef IS a
   legitimate material input when a concrete Host Binding is material and
   is exactness-matched by the closure pass), identical exact subject

   recovered from the minted request — Manifest identity+digest, exact
   target list, binding target/profile, request DAC/reference profile,
   implementation/host-binding inputs when material — must equal the
   validation/result subject exactly), ONE validation authority local to
   the two views of the SAME record (never peer authorities), no
   contradictory dispositions inside one co-stored record, validator
   designation (C113) — with the frozen 12-pass order documented on the
   verifier;
2. `classifyDacV0041CompatibilityPrecedence` — the frozen deterministic
   capability/currentness/unsupported/invalid/stale precedence for
   C84/C85/C98/C99/F-08, COMPOSING (never restating) the A41-001
   foundation Steps 0–3 (descriptor establishment -> capability kind
   blocked/missing-capability with target not judged -> structural
   invalidity FAIL_CLOSED dominating staleness -> STALE -> INCOMPATIBLE
   unsupported binding target), then the compatibility-specific rungs:
   C99 binding-check misclassification (REJECT-class, remains
   binding-authority evidence), §4.2 refusal-evidence closure validation
   (every supplied entry must verify as a complete substantive closure;
   non-substantive negative evidence is never silently dropped), C98
   contradiction (never select only the favorable result), polarity-
   neutral C157 result currentness (invalidated dominates; stale/
   superseded => STALE for favorable AND unfavorable results), polarity-
   neutral C113 validator designation (an undesignated validator can
   drive neither COMPATIBLE nor INCOMPATIBLE), the C143 material-refusal
   block (a COMPATIBLE claim cannot close while substantive refusal
   evidence stands), the negative-evidence ceiling (asserted COMPATIBLE
   requires exactly one consistent, current, designated favorable
   produced result; refusal/negative evidence alone can never manufacture
   a compatibility PASS; compatibility INCOMPATIBLE is backed only by
   produced unfavorable authoritative compatibility results — never by an
   AuthorityRefusalRef, C142), then the bounded verdict;
3. `verifyDacV0041AuthorityRefusalEvidence` — §4.2 substantive
   refusal-evidence verification for the frozen refusal seams
   (compatibility is NOT one — it carries its own INCOMPATIBLE polarity,
   C142): the COMPLETE §4.2 closure (exact request/initiation, exact
   subject/scope/profile, refusing issuer AND its designation, seam kind,
   negative decision, issuance provenance and issuance point — all

   `canProduceCompatibilityPass: false`.
