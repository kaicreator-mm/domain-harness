# DomainHarness v0.2 T-021 — G32 / AC-44 Script migration validation

This document defines the stable, reproducible validation for the T-021 compatibility slice. The exact candidate commit SHA is recorded in the GitHub validation evidence on Issue #120 / its PR after the final write; the document deliberately does not self-reference a commit SHA.

## Authority and scope

- Task: T-021 — v0.1 `script` → Script Domain Tool migration equivalence.
- Gate: G32 / PRD AC-44.
- Scope is limited to `packages/domain-harness-compiler/src/compat/v01-script/**`, `tests/migration/v01-script/**`, and this validation directory.
- No v0.2 Runtime central wiring is changed.

## Reference scenario

`tests/migration/v01-script/fixtures/` freezes one non-trivial deterministic v0.1 Script. The Script performs numeric normalization, aggregation, checksum derivation, and a decision result for two deterministic inputs. The legacy Workflow has an unconditional `done` transition to `completed`; migration must preserve that public transition while replacing only the legacy top-level Script invoke with a synthetic Script Domain Tool.

The comparison intentionally covers public observable behavior only:

1. v0.1 Script output;
2. generated v0.2 Script Domain Tool output;
3. the migrated Workflow `done` transition target.

Internal run ids, effect ids, package ids, storage layout, and Worker implementation details are not compared.

## G32 command

From a clean checkout of the exact candidate SHA on Node.js 22+:

```bash
npm ci
npm run build -w @kaicreator/domain-harness
npm run build -w @kaicreator/domain-harness-compiler
npm run build -w @kaicreator/domain-harness-node
node --test tests/migration/v01-script/v01-script-equivalence.test.mjs
```

The focused test verifies:

- deterministic synthetic Tool/binding identity from workflow id + state id + logical Script ref + frozen source digest;
- relocation stability and source-content addressability;
- legacy `invoke.script` becomes `invoke.tool` without mutating sibling Workflow structure;
- the synthetic Tool requires `script-execution@1` and uses a per-Script compiled binding id;
- `bundleScriptTool()` produces a `.node.mjs` target artifact before Runtime execution;
- v0.1 `ScriptExecutor` and v0.2 `NodeScriptExecutor` produce the same expected JSON for both deterministic cases;
- the public `done` transition remains `completed`;
- missing/mismatched frozen source and missing target Script capability fail closed.

A PASS is valid only when the GitHub evidence names the exact tested commit SHA and the command above exits successfully. Minimal CI is separate evidence and does not substitute for G32.
