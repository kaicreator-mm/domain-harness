## Scope

T-020 is a build-time compatibility task. The compatibility translator lives under `packages/domain-harness-compiler/src/compat/v01-expr/` and only rewrites frozen v0.1 `invoke.expr` nodes. It does not modify Runtime assembly, Tool execution wiring, persistence, or the sibling script-migration task.

For every legacy expression invoke, the translator:

1. fails closed when expression source is missing;
2. derives a deterministic `sourceIdentity` from the normalized expression source;
3. derives the synthetic Tool id from workflow id + state id + source identity;
4. replaces `invoke.expr` with `invoke.tool` while preserving call-site `input` and `timeoutMs`;
5. emits an effect-free synthetic Expression Domain Tool descriptor containing the expression source and permissive JSON output schema used by the existing portable `ExpressionToolExecutor`.

Filesystem location and call-site input/timeout metadata are intentionally not part of expression source identity. The same expression Tool therefore remains stable when the package is relocated or only call-site metadata changes; changed expression source changes the synthetic Tool identity.

## G31 reference scenario

The committed fixture is intentionally non-trivial. One expression derives three output fields and branches on `input.score >= 80`; the validation executes both sides of that branch:

- `alpha`: score 91 → `approved` route, derived weighted score and summary;
- `beta`: score 63 → `review` route, derived weighted score and summary.

The legacy side executes the frozen v0.1 `StepDispatcher` `invoke.expr` path. The migrated side executes the generated descriptor through the portable `ExpressionToolExecutor`. Both use the same deterministic input and logical clock. The resulting output is then passed through the frozen v0.1 `RouteEvaluator` using the reference workflow's real `done` routes, so the selected target and output are compared rather than a test-invented state label.

The comparison is limited to contract-relevant observable route/state target and output. It deliberately does **not** compare synthetic Tool ids, internal run ids, persistence layout, timestamps, or other non-semantic implementation details. This selected scenario emits no Domain Messages, so emitted-message comparison is not applicable.
