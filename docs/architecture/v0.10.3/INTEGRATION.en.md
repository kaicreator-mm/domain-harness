# v0.10.3 selected LLM integration

[中文](INTEGRATION.zh-CN.md) · [L2 freeze](L2_FREEZE.en.md)

This is a version-branch integration, not a statement that v0.10.3 has been released. The neutral `dh.llm.generate/1` types, constant and guards are exported by `@kaicreator/domain-harness-contracts`. The Node Host exposes independent `@kaicreator/domain-harness-host-node/llm/openai` and `/llm/anthropic` subpaths. Import only the selected Host binding; importing the Host root does not load either provider client. The two clients accept an SDK constructor from trusted Host code. Credentials, endpoint and model policy stay in the Host and never come from a prompt or the sealed Business package.

BUILD selects zero, one or both Capability modules. A Business declares an explicit `llmViaOpenAI` route to `llm.openai.generate`, or `llmViaAnthropic` to `llm.anthropic.generate`, with handler `generate`; both require two distinct routes. These Capability modules declare `externalEffect: true`. A route is a composition decision, not an effect permit: an actual call still needs the existing K-issued Permit and the selected Host's trusted binding. OpenAI's C imports the deployment-provided `domain-harness-openai-host` binding; Anthropic's C reads the immutable `__dhV0103AnthropicHostGenerate` Host binding. Configure only bindings selected in the App, without cross-provider credential fallback.

Construct requests with the neutral Contracts DTO and validate them at the Host boundary. Provider-reported usage and request IDs are observations, not invented counts or idempotency guarantees. Tool proposals are bounded data; they confer no Tool or K authority. Before-send deadline or cancellation refuses without outbound I/O. Once sent, timeout, cancellation, HTTP 408 or 504 can leave the outcome unknown: do not blindly retry. In the existing K implementation, the Journal records the dispatch exception as `failed` without a `zeroExternalEffect` proof and retains the admission fence; that combination holds the uncertain outcome for reconciliation. A failed Journal status alone is not proof that the remote effect did not happen.

The ordinary trusted-deployment path remains available. `VERIFIED_PROVIDER_BUNDLE_V1` is opt-in and checks an independently approved subject/closure and an installed, self-contained static ESM Provider artifact before evaluation. Its bounded closure is not a general verifier for arbitrary npm dependency graphs; unsupported graphs fail closed. Preserve the protected approval separately from mutable deployed files. Offline Guided Journey and the existing selected Meta workflow remain independent of the optional LLM routes.
