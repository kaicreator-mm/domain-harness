## B. BUILD-selected closed-world Domain App and minimal SDK lifecycle (Product A01 pending)

**One-runtime selection (at BUILD, not SDK startup):** Package generation and BUILD produce ONE trusted, complete Node.js 24 executable Domain App, using an exactly selected compatible SDK and K/S/B/C implementation set. BUILD owns module resolution, external npm/native/Node dependencies, required interfaces, role/provider/intent/hook collisions, transitive graph compatibility and the explicit dispatcher/operation bindings. Node ESM imports are ordinary private implementation details. Version/tag selects build candidates, not runtime providers. No new multi-engine abstraction, custom package resolver, Package loader cryptographic proof service or Host-local wrapper for private JS libraries.

**Roles:** exactly one K Primary is sole State/Admission/Fence/Journal/Effect/UNKNOWN/Replay authority and creates occurrence runtimes; 0..N independently selected K Extensions contribute only bounded advisory functions. Exactly one S Primary owns semantic dispatch; 0..N S Features supply named semantic handlers. One or more Business Packages own sealed Intent/Workflow scope; selected C Packages expose named Tool/Operation handlers, storage/memory, optional native Node implementations. The BUILD rejects missing, duplicate, ambiguous and incompatible roles/providers/declared dependencies **before** emitting the App. Trusted Package implementations can use Node APIs directly; no runtime package-origin verifier is required.

**Minimal SDK execution:** `load already-generated modules → connect statically selected exports → call necessary init hooks → expose facade → execute → stop/dispose`. Package init manages resources only (DB/file/socket handles) and a failed init must not expose a partially initialized facade; successful previous modules are disposed in reverse order. Deployment checks installed artifacts, native ABI/config availability when relevant. SDK does NOT re-run BUILD source/AST/hash/module-graph/import closure/issuer-signature/currentness/approval verification, install npm modules, choose a different Package or start per-Package engines. A missing actual executable hook/runtime resource fails quickly; this is not a second BUILD verifier.

**Dispatch:** S Primary uses known compiled feature bindings. K enforces live Guard/State CAS/actual caller-policy/Effect rules **once before** an irreversible transition; these checks depend on changing requests/outcomes rather than static Package trust. Ordinary local/helper imports need no Tool wrapper, **but Effect authority is semantic, not determined by whether a library call is public or private**: any business-meaningful external state-changing/irreversible operation covered by CT-04/EX-01..04 MUST flow through **K Primary Admission → BUILD-selected C Operation/adapter → K effectId/Journal/UNKNOWN**, regardless of whether the transport uses npm, built-ins or a native library. Business/S/Package-private helpers MUST NOT independently dispatch such governed Effects; private reads/computation and Package-owned resource init/dispose remain ordinary calls. The accepted code/contract/BUILD and actual K dispatch boundary enforce this selection, **not a new SDK AST/network sandbox**. K remains the sole authority; this is consistent with proposed Product A01 P1-2 and its §3 Host scope mapping.

## C. Kernel advisory extension feasibility (material UNKNOWN; not yet qualified)

K extensions are useful only if genuinely separate and **non-authoritative**, not if they repackage State/Journal/Effect logic. Candidate hook examples:

- 'admission-budget-advice/v1': consume a frozen/redacted proposed workflow step and immutable hard budget profile; return a bounded suggested step/time ceiling. K Primary clamps/revalidates against its OWN admitted hard limits; malformed, oversize or forged advice is ignored/typed denied, never a permit or success decision. A missing optional hook leaves Basic Primary behavior unchanged.
- 'recovery-diagnostics/v1': consume an immutable, permission-filtered projection of outstanding UNKNOWN/terminal correlation IDs; return prioritized bounded **observation-only** diagnostic hints. K independently decides recovery/query/commit; the hint cannot mark UNKNOWN terminal, trigger a Tool/Effect or skip a fence. On absence the Primary's conservative recovery continues.

**Advisory replay/liveness rule (research R1 review #1151, P1-1):** Advisory consultation may be pure and bounded before Admission, but creating a durable advisory/observation record MUST NOT precede or veto the Kernel's own replay/conflict adjudication. Any optional observational append occurs only after authoritative K turn disposition (or through a proven K-coordinated bounded same-CAS path), has complete subject/tenant/B/workflow/instance/turn identity, and reports append failure separately without changing the original K receipt. Replayed identical messages cause zero new state, journal, effect or advice-observation writes; different authorized instances may reuse a messageId without advisory key collision. Product #1110 payload-conflict identity remains a separately implemented K02 invariant, NOT retroactively true of v9. Tiny Basic-only must not acquire a new mandatory pre-admission persistence dependency merely because the v10 advisory plane exists. Targeted P/N for equal-input replay, different-input conflict after K02, and cross-instance same-messageId reuse is required at the actual selected K/Node seam.

## D. Turn identity, fence, dispositions and external Effect

**L2-R1 P1-01: canonical physical multi-B address (DESIGN FIX, NOT CODE PASS).** ALL K-owned durable keys use one unambiguous canonical occurrence tuple: `[deployedAppId,tenantId,appId,businessPackageId,workflowId,instanceKey]`, encoded by bounded injective length-prefixed UTF-8 (or an equivalently unambiguous canonical encoding). **`deployedAppId` is the stable logical deployment identity for this App lineage, not a unique ID per BUILD or release; a separate immutable selected-build/subject revision pin is stored in K authoritative occurrence metadata so existing instances retain their original version after successor activation.** The next App version must not accidentally create a new physical namespace merely because BUILD ran again. `recordKind` and turn/effect identifiers extend the same prefix for authoritative State, CAS fence, Journal/Effect, Disposition/original receipt, UNKNOWN/callback correlation, lane/cursor and recovery records. Never derive physical keys from workflowId+instanceKey alone or from a bare messageId. The BUILD-assigned deployedAppId is trusted and does not need runtime signature/issuer revalidation. Each B has disjoint K keys even with identical workflowId and instanceKey, including across competing writers/restarts. Malformed/missing B or legacy ambiguous addresses fail typed before persistence I/O; no pre-1.0 migration. P/N two B sharing workflowId+instanceKey, independent State, CAS, Journal, Effects, replay and restarted readback; cross-B/wrong subject cannot alias physical target.

**L2-R1 P1-02: original exact receipt replay (DESIGN FIX, NOT CODE PASS).** Persist the complete original logical acknowledged receipt (target/turn identity, result/status/revision/payload/correlation as it was actually acknowledged) as **immutable authoritative replay data in the same atomic CAS commit that persists its admitted State and fence**. Use an actual State+receipt multi-record transaction (selected Node SQLite physical CAS already offers `transact`) OR a receipt ledger embedded inside the same CAS'd occurrence document. Any best-effort Disposition is only a derived/index cache; an optional append failure cannot delete original replay truth. The 16-entry admission history is only a bounded recent index: eviction may discard an index pointer, NEVER the authoritative receipt while the dedup contract is in force. If the atomic original receipt cannot persist, the turn does not commit and no Effect is dispatched. A later external terminal result is separately admitted when real evidence exists; the original accepted/UNKNOWN acknowledgement never becomes a fabricated terminal success. Identical target/messageId/intent/canonical input replays saved original logical receipt with `idempotentReplay=true`, no new admission/journal/state/effect. Changed input/intent conflicts, and unavailable durable replay truth refuses typed. P/N original nontrivial receipt, dropped derived disposition, later state changes and 17+ more turns, restart, concurrent heals and identical retry must return original immutable content (not current snapshot), changed-input conflict, permanent store failure typed.



**K01 / #1108 reservation**: Authoritative same-CAS occurrence record contains monotonic revision, active admission reservation/attempt ID, fenced work identity and effect phase. Before ANY potentially non-idempotent remote dispatch, K must durably reserve the single intent/effect identity using true CAS. A second Host at same state revision must see the reservation and refuse/join/reconcile, **not take over by timestamp/lease expiration alone**. K commits terminal only on matching reservation, current epoch and verified terminal provider outcome. Crash/ambiguous dispatch retains an UNKNOWN/reconcile state with the same idempotency key; no blind retry unless the adapter supplies independently verified idempotency/replay proof. The protocol must specify recovery of a reservation with no remote dispatch (NOT_DISPATCHED proof) separately from uncertain dispatch; unavailable CAS / unsupported adapter returns a typed safe refusal. Two real Node processes with SQLite true CAS + non-idempotent fake downstream must falsify any orphan success / second writer success.

**K02 / #1109 + #1110**: Control-turn identity is bound to occurrence (tenant/app/B/workflow/instance and sealed K module), turn source/kind, intent and (for any turn carrying request contents) *canonical input digest*. Client key reuse: same target + messageId + intent + canonical identical input returns original receipt only with no new Admission/State/Journal/Effect; different intent or input returns 'ADMISSION_TURN_DISPOSITION_CONFLICT'. Select input encoding: bounded descriptor-safe JSON subset (null, strings, booleans, finite numbers, dense arrays, own enumerable safe-key plain objects), normalize numeric -0 to 0; reject accessors, prototype-poisoning keys, cycles, non-finite numbers, BigInt, functions, symbols, holes or oversized/deep inputs. Input property *absent* has a distinct canonical marker from explicit null; object keys are NFC-validated and sorted by UTF-8 byte sequence, duplicate normalized keys refused. Encoding version included in digest domain; reject unsupported/unknown encoding versions. Do not hash stringify's incidental insertion order or read getters.

Timer/deadline and child-terminal turns use stable source IDs tied to their sealed scheduling/child origin plus immutable payload digest where they carry data; callback turns include the expected callback correlation and canonical delivered payload digest. Redelivery of identical turn is idempotent, changed source/payload conflicts. An already committed history or Disposition **missing the required digest** refuses typed identity-unknown, NEVER replays as equal or invents digest; pre-1.0 migration of old storage is not required.

The same-CAS **authoritative original receipt ledger**, not the bounded recent-turn index, is replay truth when optional Disposition append is lost. On index eviction any optional healing may conditionally rebuild the derived Disposition from the immutable persisted receipt, never from the current workflow snapshot; the authoritative receipt is not evicted while replay is promised. Lost optional append never blocks subsequent new turns. P/N: 17+ turns, original nontrivial receipt, intervening State change, lost derived append, restart/concurrent replay, changed-input conflict and persistent storage failure.

**C01 / #1138 Host effect port**. Selected binding (capabilityId, operationId, handler/adaptor revision, sealed root/subject digest, caller/B scope and effect class) is exact. The K-assigned effectId + occurrence/attempt/revision deterministically yields the external idempotency key. Protected Host passes that key **to** the selected provider adapter, with no credentials exposed to S/B/LLM; identity is bound before dispatch. Persist phases 'NOT_DISPATCHED', 'DISPATCH_ATTEMPTED', 'ACCEPTED_RUNNING', 'TERMINAL_SUCCESS', 'TERMINAL_FAILURE', 'UNKNOWN_RECONCILE' with traceable AttemptRef and optional providerRef. Provider ACK/202 only advances to accepted-running; never terminal. Timeout or process death after attempted dispatch becomes UNKNOWN until authenticated correlated callback or read/query reconciliation. K admits every terminal transition as a separately authenticated and deduplicated control turn using current pin/fence/authority. Wrong adapter, stale target/revision, revoked grant, duplicate/late callback or claimed terminal without proof cannot commit. A provider with no proved idempotency or reconciliation cannot be admitted for non-idempotent automatic retry. No global exactly-once claim, cancellation proof, runx-specific API or new scheduling engine.

## E. Semantic/Tool split and bounded Workflow

Semantic S Feature contracts (direct selected semantic dispatch, not general Agent-visible Tool): Rule/Guard, four-source DecisionResolver, compiled SemanticDecision, Workflow iteration, child/WAIT/RESUME, Context packing, dependency analysis, Shadow comparison and Candidate validation. C TOOL_READ: current authorized model inference/retrieval/search/calculation, scoped memory.get/search, selected cache query. C TOOL_EFFECT: authorized external job/device/HTTP and memory.put/delete, storage/cache writes under an exact effect policy. OBSERVATION_APPEND: bounded append-only Evidence/receipt with its OWN scoped Host observational writer namespace, current source attestation and separate error result; never K Journal / business Effect completion. Model-facing Tool projection defaults to reads; model content is proposal data, never a K permit.

Decision resolution: current Rule -> exact schema/revision/provenance-matched semantic cache -> approved pinned reusable procedure -> budgeted Model/Query fallback. A miss can fall through; malformed/stale/unauthorized hit denies, not silently reuses. Count actual Model invocations or 'unmeasured', never synthesize a count of zero. Each decision returns source, observed dependencies, exact stable input/result/pin and a truthful optional DecisionResolutionReceipt. An optional Evidence failure is 'not_recorded' without rewriting a committed ACK. No durable-mandatory receipt without an independent atomicity proof.

Workflow loop: finite step count, runtime/time/token/tool budgets, typed terminal statuses, one selected K admission per state change, persisted WAIT/RESUME, correlated child/timer/callback turn, restart and duplicate-safe effect. A bounded Agent Loop is just this S/B Workflow with explicit read Tool permissions, no Agent Runtime and no model-driven internal Kernel state id.

Memory C: namespace tenant/app/B/agent/thread, authorization per operation, revisioned put/delete CAS, get/search with scope and TTL/provenance; persisted in selected C/Host store, not K Journal. Context S constructs immutable budgeted inputs from current state/observations/history/memory with source versions and revocation/currentness, without leaking hidden B data.

## F. Shadow Evidence and new version governance

Runtime Evidence projection is append-only and provenance-bound to observed K transitions and selected S decision facts; no observation can assert a false K commit or authorize business effect. Shadow S comparator accepts approved Candidate data and an exact pinned baseline, runs in isolated SIMULATION/no-effect profile with separate disposable Cache/Procedure/Memory/Evidence namespaces and read-sanitized snapshots. A candidate may perform only shadow-safe read/model/evaluation under explicit budget; it must never dispatch production TOOL_EFFECT, populate production semantic cache or update business State. Shadow report may be recorded as OBSERVATION_APPEND in an explicitly nonproduction provenance namespace.

Candidate shapes Rule/DecisionProcedure/Skill/Workflow require deterministic schema/allowed event and tool set, bounded-cycle/cost and pin validation. Selection changes only when BUILD produces and deployment activates a **new trusted executable Domain App**; SDK cannot dynamically change selected Package graph. Running occurrences stay on their original deployed App/version. Stable fallback is an exact qualified immutable identity, never floating latest/current. Recurring Meta Workflow (P1) is ordinary Business Workflow; its proposal does not self-approve activation.

## G. Multi-B query confidentiality

P0 public query accepts exact scope 'businessPackageId' (or a BUILD-sealed unambiguous target reference) together with 'kind=instance', 'instanceKey'. Host first establishes caller, allowed B/workflow and active subject, then does single target K snapshot lookup. Unscoped query enumerates **only caller-authorized B targets** and returns a snapshot exactly when there is one eligible visible match, typed no-match for zero or typed 'INSTANCE_SCOPE_AMBIGUOUS' for >1 visible matches. Hidden B presence never changes visible result or error category; a denied explicit target returns a non-oracular scope denial/unknown. No physical package first-match. P1 queryMany, if admitted, independently authorizes each target and reports per-target failures; never implies distributed atomicity.
