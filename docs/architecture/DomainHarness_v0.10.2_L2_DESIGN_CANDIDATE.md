What remains outside K is (a) two legacy key literals and the K02 prefix grammar used by deployment/activation (INV s.9) and (b) the field names of four documents the gate reads. These are the only K-private facts held outside K Primary.
2. *Why a contracts mirror is not what R1 P1-1 objected to.* R1 P1-1 objected to the compiler **silently** mirroring K-private schemas in several files with no authority or drift fence (`digest.ts:46-50` is one such comment-only fence for two literals). This design collapses every mirror into one read-only module whose owner is the K Primary task (changes to it and to K go together, reviewed by the same owner), exports **no writer**, and is verified in both directions against the real K Primary by an executable test (s.2 negative test 1) - drift fails CI instead of being found at runtime.
3. *Why not literally "K-owned".* K Primary is a sealed zero-import module (`INV s.1.1`); it cannot import a shared file, and exporting its builders would change its bytes and every BUILD digest (rejected alternative a). The contracts module is therefore the smallest shape that keeps K bytes, wire literals and the single-writer rule unchanged.
4. *If Product rejects this shape:* fall back to alternative (a) (K exports `legacyKernelDocKeys`/`scopedKernelDocKeys` read-only; one-time K digest change, requires a Product-visible amendment of the "byte-stable where possible" expectation) - the rest of the design is unaffected because only `kernel-doc-protocol.ts` and its parity test change.

## 8. Subscribe / stop - minimal design (PD-02; no new runtime)

| Item | Content |
| --- | --- |
| **Decision** | `subscribe` is a thin fan-out over the K Primary's **existing, optional, best-effort receipt observation**: the runtime factory option `observe` (`kernel-mechanism-v1.mjs:64,4764`; `safeObserve` at admission/replay/terminal receipts, failures swallowed, "not an authority path", `:5895-5900`) is currently wired to a no-op (`activation.ts:946-948`). T06 replaces that no-op with a per-activation registry. `subscribe(selector, listener)`: (1) `assertOpen`; (2) same preconditions as `query` - `queryAuthority` present and `deploymentIdentity` present, else `QUERY_AUTHORIZATION_REQUIRED` / `QUERY_DEPLOYMENT_REQUIRED` (`activation.ts:738-754`); (3) resolve + authorize the exact `V10ScopedQueryTarget` through the same multi-B selector (`#querySelector(...).query(selector)`), so unselected/hidden/foreign B is refused with the identical non-oracle answer (`v010-authorized-multib-query.ts` header); (4) register the observer for that B's runtime and `workflowInstanceId = ${workflowId}:${instanceKey}` (`kernel-mechanism-v1.mjs:5254`), forcing the K runtime creation path `#runtimeFor` (`activation.ts:910`); (5) on each K receipt, deliver only when `receipt.occurrence.workflowInstanceId` matches, **re-running `authorize(principal, target)` on every delivery** and dropping + unsubscribing on refusal - the exact pattern of the v0.8 gateway (`kernel-gateway.ts:1230-1260`); listener exceptions are swallowed (observation is non-authoritative, CV-12). `stop()`/`dispose` clears the registry before reverse-disposal; `unsubscribe()` removes one entry; delivery after stop is impossible (`FACADE_CLOSED` on new `subscribe`). |
| Rejected | durable cursor/reconnect/coalescing (PD-03, `OUT_OF_SCOPE_V0102`); reusing the v0.8 `ScopedEventHub`/credential model (needs HostCredential machinery not on the v0.10 path); polling `query`. |
| **Escalation boundary (PD-02)** | This is **not** broad new runtime design. It would become so, and must be escalated to Product, if any of these is required: delivery across OS processes or after restart (K `observe` fires only in the process that executed the turn - two-process Apps see only their own turns), at-least-once/ordering guarantees, or a receipt shape narrower than K's outward receipt (K receipts carry `instance` snapshot and `attribution`; whether subscribers may see exactly what `query` may see is **NOT_VERIFIED**, O8). |
