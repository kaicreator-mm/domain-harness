# DomainHarness v0.10.2 · Troubleshooting

[Index](index.md) · [中文版](../zh-CN/troubleshooting.md)

Collect the **typed error code, exact source SHA, public API, smallest safe input and literal command EXIT**. Never dump sensitive K documents, permits or consumer logs.

| Symptom | Likely cause | Bounded next step |
| --- | --- | --- |
| Public package `ERR_MODULE_NOT_FOUND` | Packed closure/lockfile | A Git tag does not prove registry publish; install actual selected tarballs |
| Legacy `compiler/v10build` import denied | Retired private API | Move producer to `domain-harness-build`, runtime to `microkernel` |
| `V10_APP_INVALID` | Untrusted/unsealed App or malformed store | Inspect BUILD ABI/hash/closure, never compile at runtime |
| `QUERY_SELECTOR_INVALID` or multi-B denial | Explicit target or caller authorization | Resolve business/workflow/instance and genuine Host scope |
| Effect denied or UNKNOWN | K permit, selected C declaration, external attempt | Do not bypass permits or claim synthetic success |
| SQLite driver missing | Optional Rich driver absent | Install `better-sqlite3` only for selected native path |
| Tiny plain-file store concurrent writer | Unsupported multi-process scenario | Use transactional Rich SQLite CAS |
| `FACADE_CLOSED` | Runtime already stopped | Activate a new facade |
| Node child-process capacity errors | OS/CI runner | Classify separately from SDK functional failures |

Choose the **smallest matching physical proof**: `projection-smoke.mjs` for selection, `authoring-template-check.mjs` for selected BUILD/effects, `clean-consumers.test.ts` for installed Tiny/Rich. The [original troubleshooting matrix](../../manual/V0102_TROUBLESHOOTING.md) is a detail source.

When a real SDK contract breach is established, follow [Issue workflow](feedback.md), avoiding duplicates or OS-only product reports.
